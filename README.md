# Real-Time-Activity-Logger

A scalable event-driven microservice using Node.js,Express and Kafka for real-time processing.

### Contents:

1. Implement a Kafka producer and consumer to process user activity logs.
2. Store processed logs in MongoDB with proper indexing.
3. Deploy the service using Docker and Kubernetes (K8s) on (Google Cloud/AWS) free tier or any other server
4. Follow DDD (Domain-Driven Design) principles in structuring the service.
5. Expose a REST API to fetch processed logs with pagination and filtering.

### Setup

`docker` and `docker desktop` must be installed.

#### Build image 

`OR` the latest image on docker hub will be pulled. 

```bash
docker build -t log-service:v1.0 .
```

#### Start k8s cluster

```bash
kubectl apply -f k8s/ -R
```

#### Start ingress controller

##### Docker Desktop
```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.10.1/deploy/static/provider/baremetal/deploy.yaml
```
`OR`
##### Minikube
```bash
minikube addons enable ingress
```


#### Add ip address in `hosts` file

##### Docker Desktop
```bash
127.0.0.1               loggingservice.com
```
`OR`
##### Minikube
```
<ingress-ip-address>    loggingservice.com
```

Open Any broswer and go to `http://loggingservice.com/health`


#### Useful Commands

```bash
watch kubectl get all
```

### Architecture Choices

1. Entities
   1. `Log` is the only considered.
   2. `ID` is generated by Mongodb and not using auto-increment as the system is designed to be scalable
2. Value-Objects
   1. The level of the log is constant; therefore can be considered as a value Objects
3. No Aggregates
   1. the project is simple to use a one.
4. Logs Consumer
   1. Done in a separate thread using `new_worker`.
   2. Usage of a `buffer` to send logs to Mongodb while the pub/sub would be better, but I think `setInterval` is enough for such application.
5. Server Pod waiting for kafka and mongodb
   1. Making server pod waits for kafka and mongodb using init containers in pod.
6. Mongodb Index
   1. The index is added to the level field.
   2. Multiple indices degrade performance; therefore, I have stop thinking at this point.
